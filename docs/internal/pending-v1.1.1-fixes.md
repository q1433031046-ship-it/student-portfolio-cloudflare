# v1.1.1 待发布修复记录

> 状态：已定位，暂不提交到生产版本。等待明确发布指令后统一修复、测试和部署。

## 1. 后台封面排版与前台显示不一致

### 现象

后台封面排版画布中，标题可以保持一行；前台正式封面中，同一标题字号明显变大并自动换成多行。文字位置大体正确，但字号、有效宽度和换行结果不一致。

### 已定位原因

- 后台标题使用 `clamp(28px, 4vw, 62px)`，前台使用 `clamp(58px, 7vw, 112px)`。
- 前台标题和简介另有 760px / 440px 最大宽度限制，后台没有相同限制。
- 两端都使用浏览器视口单位 `vw`，而不是封面容器单位，因此后台嵌入画布与前台全宽画布计算结果不同。
- 手机端前台改为 4:5 封面并使用另一套排版规则，后台仅提供 16:9 编辑预览。

### 计划修复

- 后台与前台共用同一个封面文字渲染组件和同一套样式参数。
- 字号改为按封面容器计算，不再按浏览器视口计算。
- 统一标题、简介和项目信息的宽度限制与换行规则。
- 后台增加桌面 16:9 / 手机 4:5 预览切换。
- 增加前后台渲染一致性回归测试。

## 2. 上传封面后，后台偶发裂图；快速预览正常

### 现象

图片上传成功后，后台裁切或封面排版预览有时显示裂图；点击快速预览后，同一张图片又能正常显示。

### 已定位的主要原因

这是“图片已上传，但草稿还没有保存”时的预览时序问题：

1. 上传完成后，浏览器内存中的作品数据立即获得 `/api/media/...` 地址，并被标记为未保存修改。
2. 当前组件还挂载时，会使用本地 `blob:` 临时地址预览，所以通常正常。
3. 如果用户在保存草稿前切换作品、切换后台栏目或触发组件重新挂载，本地临时地址会丢失，预览改用 `/api/media/...`。
4. 目前媒体读取接口会先检查该媒体 key 是否已经存在于服务端保存的草稿文档中。由于草稿尚未保存，该请求返回 404，于是后台出现裂图。
5. “快速预览”会先自动保存草稿，再打开预览；保存后媒体 key 已进入服务端草稿，因此同一张图片可以正常显示。

### 次要稳定性问题

- `previewSrc` 只在组件首次挂载时从 `asset.src` 初始化，后续属性变化没有统一同步。
- 本地 `blob:` 地址替换后没有集中回收，连续上传大量图片可能造成浏览器内存占用。
- 图片加载失败时缺少自动切换到备用地址、重试或明确错误状态。

### 计划修复

- 管理员已登录时，允许读取本网站中已成功上传但尚未写入草稿引用的媒体；公开访客仍只允许读取已发布文档中的媒体。
- 保留本地预览地址直到服务端媒体地址确认可用，避免组件重新挂载后立即裂图。
- 同步 `previewSrc` 与当前 asset，并安全回收旧的 `blob:` 地址。
- 增加图片 `onError` 回退、重试和“媒体已上传，等待草稿保存”的明确状态。
- 增加“上传后未保存 → 切换作品/栏目 → 后台仍可预览 → 保存 → 快速预览正常”的回归测试。
