# 稳定性与封底升级工作计划

> 开发分支：`upgrade/stability-footer-draft`
>
> 规则：开发和测试阶段不修改正式版本号，不合并 `main`，不发布生产。全部验证通过并由项目负责人确认后，才在最终发布提交中更新版本号。

## 目标

1. 修复管理员首次初始化卡住和正确密码偶发无法进入。
2. 将首次初始化口令、管理员密码、恢复码、登录会话的职责拆开。
3. 每次正式版本升级后，使用最新恢复码完成一次密码重置，并生成新的恢复码。
4. 修复上传图片后后台裂图、切换作品仍显示上一张封面。
5. 统一后台封面排版、快速预览和正式前台的渲染。
6. 将程序内部校验路径转换为小白可读说明，并准确定位到作品、内容块和字段。
7. 支持视觉文字和正文手动回车换行。
8. 增加多张封底，位于全部作品之后、现有页脚之前，不折叠。
9. 重写一键部署、后台找回、恢复码和升级教程。

## 空白字段策略

原则：用于展示的内容允许留空并自动隐藏；系统识别所需内容使用安全默认值，不用“必须填写”阻断学生。

### 允许留空并自动隐藏

- 职业标题、求职方向、个人定位、状态短句。
- 邮箱、电话；为空时隐藏对应联系入口。
- 联系页眉题、主标题、说明。
- 作品年份、简介、项目难点、解决思路。
- 内容块眉题、标题、正文、图注。
- 作品区大标题。
- 封底的全部文字层。

### 保留系统默认值

- 网站名称为空时使用“学生作品展示”。
- 作品名称为空时后台使用“未命名作品”作为识别名，前台按显示开关决定是否展示。
- 分类名称为空时后台使用“未命名分类”。
- 没有视频时长为 `00:00`。

### 仍需严格校验

- 管理员密码、系统恢复码、首次初始化口令。
- 数据 ID、媒体类型、资源 key、裁切和坐标范围。
- 非空邮箱必须是有效邮箱；非空电话必须符合电话号码格式。

## 错误提示与精确定位

- 将 `projects[1].detailBlocks[0].body 长度无效` 转为：第 2 个作品 → 第 1 个内容块 → 正文。
- 显示当前字符数和允许范围。
- 主按钮改为“定位并修改”。
- 点击后依次切换栏目、选择作品、展开内容块、滚动、红框、聚焦。
- 在输入阶段显示字符计数和行内错误，不等保存后才报错。

## 多行文字

- 视觉排版文字和内容正文：Enter 插入换行；Ctrl/Cmd + Enter 完成编辑；点击外部保存。
- 后台、快速预览、正式前台统一保留换行。
- 邮箱、电话、年份、分类名、密码和恢复码保持单行。

## 多张封底

- 多张纵向连续展示，不轮播。
- 首图展开后才显示。
- 位于所有作品之后、现有页脚之前。
- 每张封底拥有独立图片、文字内容和排版。
- 支持纯图片、系统排版、自由排版、裁切、排序、复制、删除。
- 桌面和手机预览与裁切分别验证。

## 固定首次初始化口令

公开指南固定使用：`StudentWeb2026A1`。

- 新部署完成后立即进入 `/admin` 初始化。
- 初始化成功后该口令不能再次创建管理员。
- 认证重构后，管理员密码、恢复码和登录会话不再依赖该口令。
- 已部署旧网站不要求立即修改 Cloudflare 中原有口令，升级时通过最新恢复码迁移。

## 教程必须强调

- 恢复码每使用一次都会生成新码，旧码立即失效。
- 最新恢复码同时用于忘记密码和下一次正式版本升级。
- 必须保存 Cloudflare 账号、前台地址、后台地址、最新恢复码。
- 后台地址丢失：Cloudflare → Workers & Pages → 找到项目 → 复制 workers.dev 地址 → 末尾加 `/admin`。
- 二维码限制只限制访客前台，不限制管理员后台。
- 部署前先在 ChatGPT 插件/连接器中连接 GitHub 和 Cloudflare；失败时改走官方 OAuth，避免反复在对话中授权。

## 开发与发布顺序

1. 数据模型、空白字段和多行兼容。
2. 管理员初始化、登录、恢复码轮换和认证迁移。
3. 结构化错误、准确定位和字符计数。
4. 媒体预览状态重构。
5. 封面前后台渲染统一。
6. 多张封底。
7. 教程与 GPT 引导词。
8. 单元测试、类型检查、Lint、生产构建。
9. 独立测试 Worker / D1 / KV 验证新站和旧站升级。
10. 浏览器与手机人工验收。
11. 项目负责人确认。
12. 最终提交中更新版本号并合并生产。
