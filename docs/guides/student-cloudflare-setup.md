# 学生作品展示：GPT 引导部署与使用指南

这份指南给完全不懂代码的学生使用。原则只有一个：**先打开 GPT，再由 GPT 带着你去部署。不要自己先点 Cloudflare。**

## 一、部署前先准备好

开始前请准备：

- ChatGPT 账号；
- GitHub 账号；
- Cloudflare 账号；
- 一个能正常收验证码的常用邮箱；
- Chrome 或 Edge 桌面浏览器；
- 手机放在旁边，用来接收可能出现的验证码或二步验证；
- 作品图片、文字和 MP4 视频，单个视频不超过 50 MB。

Google/Gmail 账号不是强制，但如果你习惯用 Google 登录，建议 GitHub、Cloudflare、ChatGPT 尽量使用同一个常用邮箱，减少记错账号的概率。

不要提前准备 API Key、Cloudflare API Token、GitHub Personal Access Token。正常一键部署不需要这些东西。

## 二、进入 GPT 后怎么选

### 推荐模式

**优先使用 ChatGPT「工作」模式（如果你的界面里有“工作”）。** 这个模式适合持续处理仓库、网页操作、检查和部署流程。需要登录网站、授权或确认时，GPT 会停下来让本人处理。

如果账号里没有“工作”模式，不用乱找按钮：可以使用普通 ChatGPT 对话，让 GPT 一步一步指导你在自己的浏览器中完成授权和部署；如果桌面版里有 Codex，也可以把代码检查和故障修复交给 Codex。

无论使用哪种界面，正式部署的模型要求不变：

- 最低模型：**GPT-5.6 Sol**。
- 默认思考程度：**高**。
- 遇到部署失败、Cloudflare 资源绑定、数据库迁移、版本升级、账号串号或复杂报错时：改成 **超高**。
- 正式部署不建议使用“中等”。
- 如果当前账号看不到 GPT-5.6 Sol，先不要开始正式部署。

把 `deployment/DEPLOY-PROMPT.txt` 里的整段文字复制给 GPT。GPT 应当一次只指导你完成一个步骤，不要一次给你很多操作。

## 三、最重要：账号不要串

### 1. 同一个 GPT 账号，可以帮很多学生部署

GPT 账号只是“指导和执行助手”，它不等于 GitHub 或 Cloudflare 账号。

可以用同一个 GPT 账号，依次帮助学生 A、学生 B、学生 C 部署；但是每次开始前必须确认：

1. 现在要部署的是哪一位学生；
2. 浏览器当前登录的是谁的 GitHub；
3. 浏览器当前登录的是谁的 Cloudflare；
4. 当前准备创建的网站名称是什么。

如果上一位学生的 GitHub 或 Cloudflare 还登录着，先退出对应平台，再登录下一位学生的账号。**不要只看 GPT 账号是谁，要看托管平台当前登录的是谁。**

推荐每部署完一个学生，就记录：学生姓名、GitHub 用户名、Cloudflare 登录邮箱、网站地址、GitHub 仓库地址。管理员密码和恢复码不要写进公共表格。

### 2. 同一个 GPT 账号，部署到不同托管账号

允许。例如同一个 GPT：

- 第一次帮助 `student-a@gmail.com` 的 GitHub + Cloudflare；
- 第二次帮助 `student-b@gmail.com` 的 GitHub + Cloudflare；
- 第三次帮助另一个完全不同的 GitHub + Cloudflare。

每次切换时，GPT 必须先让用户确认当前浏览器里的 GitHub 和 Cloudflare 身份，再打开部署链接。发现账号不对就停止，不能继续创建资源。

如果使用 ChatGPT 工作模式里的独立浏览器/云端浏览器，也一样必须检查那个浏览器自己的登录账号；它和你电脑上 Chrome 已经登录的账号不一定相同。

### 3. 同一个 GitHub + Cloudflare 账号部署多个网站

也允许，但每个网站必须完全独立。每个网站都要有自己的：

- GitHub 仓库；
- Worker 名称；
- D1 数据库；
- `MEDIA_KV`；
- `workers.dev` 地址；
- 管理员密码；
- 系统恢复码。

部署第二个、第三个网站时必须换一个新名称，例如：

- `student-portfolio-01`
- `student-portfolio-02`
- `student-portfolio-03`

不能让第二个网站复用第一个网站的 D1 或 KV，否则作品和媒体可能串到一起。

## 四、正式部署流程

1. 打开 ChatGPT。
2. 界面有“工作”时优先进入“工作”模式；没有时使用普通 ChatGPT 对话即可。
3. 选择 GPT-5.6 Sol，思考程度选择“高”。
4. 复制 `deployment/DEPLOY-PROMPT.txt` 给 GPT。
5. GPT 先检查账号准备情况，并询问这是这个 Cloudflare 账号里的第几个作品集网站。
6. GPT 确认 GitHub 和 Cloudflare 身份无误后，再给你 Deploy to Cloudflare 官方链接。
7. 在 Cloudflare 官方页面完成 GitHub / Cloudflare 授权。
8. 如果是同一账号的第二个或更多网站，使用新的项目名、Worker 名和资源名。
9. `DB` 和 `MEDIA_KV` 必须属于这次新网站，不能选到旧网站资源。
10. 在 `INITIAL_ADMIN_CODE` 中设置至少 16 位、同时包含英文字母和数字的一次性部署口令。只在 Cloudflare 官方页面输入，不要发给 GPT。
11. 点击 Deploy，等待 Worker、D1、KV、数据库迁移和网站发布完成。
12. 打开生成的 `workers.dev` 地址，再进入 `/admin`。
13. 第一次进入后台，用刚才的一次性部署口令创建管理员密码。
14. 管理员密码要求 10 至 128 位，至少包含文字和数字，并且不能和一次性部署口令相同。
15. 系统生成恢复码后立即下载并离线保存。
16. GPT 最后检查后台、图片、视频、网站空间、预览和发布是否正常。

## 五、后台登录，用最简单的话理解

第一次设置好管理员密码后，网站会让这台浏览器保持登录 **12 小时**。

也就是说：你刚输过正确密码，在接下来的 12 小时里，再从前台点“管理”，通常会直接进入后台，不会每次都重新让你输密码。这是正常的，并不代表网站没有密码。

如果你点右上角 **“安全退出”**，登录状态会立刻失效。下一次再点“管理”，就必须重新输入管理员密码。

如果连续输错密码 **5 次**，系统会锁住后台 **15 分钟**，防止别人一直猜密码。

12 小时到期后，也需要重新输入密码。

## 六、忘记密码怎么办

在后台登录页选择“使用系统恢复码”：

1. 输入你保存的系统恢复码；
2. 设置新管理员密码；
3. 恢复成功后，旧密码失效；
4. 之前的管理员登录会话全部失效；
5. 旧恢复码立即失效；
6. 系统重新生成一份新的恢复码，请再次离线保存。

管理员密码和最新恢复码如果同时丢失，需要由部署维护人员对 D1 做管理员凭证重置。系统不会保存可以直接查看的明文密码。

## 七、这些内容绝对不要发给 GPT

不要把下面这些东西粘贴到聊天里：

- 管理员密码；
- `INITIAL_ADMIN_CODE` 一次性部署口令；
- 系统恢复码；
- Cloudflare 密码；
- GitHub 密码；
- 浏览器 Cookie；
- 长期 API Token。

需要这些内容时，由本人在官方网站或自己的网站后台输入。

## 八、网站空间与视频

后台 `概览` 最下方的“网站空间”会显示：已使用空间、剩余空间、媒体文件数，以及大约还能放多少个 50 MB 视频。

应用空间上限为 800 MiB；达到 700 MiB 时开始预警；达到 800 MiB 后停止新上传。

视频要求：MP4，推荐 H.264 / AAC，单个不超过 50 MB。视频会按 4 MiB 分片保存，并支持拖动进度条和 Range 播放。

## 九、程序升级中心

后台 `概览 → 网站空间` 下面有“程序升级中心”，可以看到当前程序版本并复制升级指令。

升级时只更新程序，不重新创建网站。必须保留：

- 当前 Worker 和网站地址；
- 当前 D1 数据库和全部数据；
- 当前 `MEDIA_KV` 和全部图片、视频、字体；
- 管理员账号、密码状态、恢复码状态；
- 草稿和已经发布的作品；
- 二维码、访问记录和后台记录。

升级前 GPT 必须读取 `UPGRADE-GUIDE.md` 和 `deployment/template-version.json`。

## 十、部署后检查

部署完成后至少检查：

1. `/admin` 未登录时会要求管理员密码；
2. 正确密码能登录，安全退出后必须重新登录；
3. 连续错误密码会触发锁定；
4. 概览里能看到网站空间和程序升级中心；
5. 上传 JPG/PNG/WebP/AVIF 图片正常；
6. 上传 MP4 正常；
7. 视频可以播放和拖动进度；
8. 保存草稿后快速预览正常，公开页不会提前变化；
9. 发布后公开页更新；
10. 二维码公开、限制、次数用尽和过期状态正常。

## 十一、给大陆用户的提醒

`workers.dev` 在不同中国大陆运营商上的线路质量可能不同。正式给客户看之前，至少使用目标用户实际使用的手机网络和宽带各测试一次首页与视频。如果线路不稳定，优先降低视频码率，再考虑更适合大陆网络的正式托管方案。

## 十二、出现问题时怎么办

不要自己反复乱点。把**报错文字或截图**发给 GPT，但不要把密码、恢复码、一次性部署口令一起截图进去。

GPT 应先确认当前学生、当前 GitHub、当前 Cloudflare、当前 Worker 和资源归属，再处理问题；如果部署过程中资源已经创建，优先修复并继续使用现有资源，不要重复创建第二套 D1/KV/Worker。
