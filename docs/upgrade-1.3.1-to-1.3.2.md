# 1.3.1 → 1.3.2 升级指令（精简版）

**适用于已运行 1.3.1 的学生项目：正式 v1.3.2 已发布，请复制以下指令到原网页版 Work 云端项目继续升级。本分支只存放说明，程序来源固定为下列正式版本。**

请在我的原网页版 Work 项目中，将已运行的 1.3.1 升级到正式 1.3.2。沿用 GPT-5.6 Sol／极高、已有连接、凭据、配置和执行回执，从未完成步骤继续。

1. 使用下列正式 v1.3.2 Release 和固定提交，核对 Tree、版本清单、原始升级词摘要及对应独立审计后，接续本项目尚未完成的升级步骤。证据不齐时停止在缺失项；不要用本说明分支、main 最新代码或旧版审计代替。
2. 保留原 Worker、数据库、媒体、Secrets、域名和免费套餐，只实施准确补丁及必要配置；已完成的升级、迁移和发布不重复。沿用不变验证，只检查补丁直接影响，不跑全套测试。
3. 先复用凭据；超时、权限不足、凭据读取失败和脚本 STOP 分开诊断。写入结果不明先读回，不盲重发。需要本人登录、人机验证或权限确认时，准备好其他事项后集中说明；不自行增加无关权限或付费。
4. 按目标版本的实际认证流程，在原 /admin 完成本人恢复码确认并保存新码；不绕过认证，不索取码的内容，不重复同版本确认。
5. 继续完成本站静态配置与完整 ZIP 准备，复用已保存/已发布成果。交付 ZIP 实际下载链接和原 Pages 上传链接；保持自动发布服务暂停，缺少本人上传操作就准确交接。

最后报告实际运行版本、首页/后台、下载故障是否解决、ZIP 与静态发布各自结果。只做少量现有媒体检查，不反复下载、构建或发布。发现新错误时保留具体错误码和失败项，不把通用 422 文案当根因。
