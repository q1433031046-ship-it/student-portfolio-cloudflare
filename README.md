# 学生作品展示｜部署与后台使用傻瓜指南

> 这是本项目唯一面向学生的公开指南。
>
> **部署前：只看 GitHub 这一页。部署后：登录自己网站的 `/admin`，点击右上角“使用教程”，可打开后台教程。**
>
> GitHub 承担部署前的公开说明；部署成功后，每个学生的网站流量由自己的 Cloudflare 账号承担。

---

## 先看懂整个逻辑

正确顺序只有这一条：

**打开 GitHub 本指南 → 打开 GPT → GPT 核对账号 → 打开 Cloudflare 官方部署入口 → 创建管理员 → 编辑内容 → 快速预览 → 正式发布。**

各入口的作用：

- **GitHub 本页**：部署前的中央指南，不消耗老师网站的 Cloudflare 请求。
- **学生自己的前台 `/`**：默认公开；也可以在后台启用二维码限制访问。
- **学生自己的后台 `/admin`**：必须通过管理员密码，只有站点本人可以编辑。
- **后台“使用教程”**：登录管理员后台后出现，直接打开后台教程。
- **后台“程序升级”**：登录后在右上角可直接点击；也可在“概览 → 网站空间”下方看到完整升级中心。
- **GPT 账号不等于托管账号**：同一个 GPT 可以帮助多人，但网站最终属于浏览器当前登录的 GitHub 和 Cloudflare 账号。

## 1. 部署前准备

### 1.1 必须准备

- 一个能正常使用的 ChatGPT 账号。
- 一个能正常登录的 GitHub 账号。
- 一个能正常登录的 Cloudflare 账号。
- 一个可以接收验证码的邮箱。
- 一台电脑，推荐使用 Chrome 或 Edge。
- 手机放在旁边，用于邮箱验证码或二步验证。

Google / Gmail **不是必须**。GitHub、Cloudflare 可以使用 Google、GitHub、Apple 或邮箱密码登录，但必须记清楚自己最初选择的是哪一种方式。

### 1.2 不需要准备

正常部署不需要提前创建：

- OpenAI API Key；
- Codex API Key；
- Cloudflare API Token；
- GitHub Personal Access Token；
- 任何长期密钥。

任何要求你把密码、Cookie、Token、一次性部署口令或恢复码粘贴到聊天中的操作，都不正常。

### 1.3 素材建议提前整理

- 姓名；
- 职业标题和求职方向；
- 一句个人定位；
- 邮箱和电话；
- 首页首图；
- 项目封面；
- 项目简介、项目难点、解决思路；
- 项目过程图片；
- H.264 / AAC 编码的 MP4 成稿视频。

## 2. 先打开 GPT：每一步点哪里

> **这一部分完成之前，不要提前点击 Cloudflare 部署链接。**

### 2.1 打开 ChatGPT

1. 在电脑浏览器打开 ChatGPT。
2. 登录自己的 ChatGPT 账号。
3. 点击“新建对话”或左上角的新对话按钮。
4. 不要进入图片生成、语音或其他无关工具页。

### 2.2 选择使用方式

- 页面里有 **“工作”** 模式时，优先选择“工作”。
- 没有“工作”模式，使用普通 ChatGPT 对话即可。
- 后续如果 GPT 建议使用 Codex 检查仓库或修复构建，可以允许；但密码、一次性部署口令和恢复码仍然只能由本人在官方页面输入。

### 2.3 选择 GPT-5.6 Sol

1. 点击页面顶部或对话框附近的模型选择器。
2. 选择 **GPT-5.6 Sol**。
3. 如果当前账号看不到 GPT-5.6 Sol，先不要执行正式部署。

### 2.4 设置思考程度

1. 打开思考程度选项。
2. 正常部署时，思考程度选择“高”。
3. 只有遇到部署失败、Cloudflare 资源绑定、数据库迁移、账号串号、版本冲突或程序升级时，才改成 **“超高”**。
4. 不建议用“中等”完成正式部署。

### 2.5 复制部署引导语

把下面整段完整复制到新对话中，不要删减：

```text
我要部署“学生作品展示”网站。请全程一步一步带我完成，一次只让我做一个主要动作，不要一次发很多步骤。

开始前请先确认：
1. 我使用的模型至少是 GPT-5.6 Sol，思考程度为“高”；复杂故障时提醒我改成“超高”。
2. 当前实际操作浏览器里登录的是哪一个 GitHub 账号、哪一个 Cloudflare 账号。
3. 这是这个 GitHub / Cloudflare 账号里的第几个学生作品网站；如果已经有其他网站，必须为这次网站使用新的仓库、Worker、D1 和 MEDIA_KV，绝不能复用旧网站的数据资源。
4. 如果同一个 GPT 账号正在帮助不同学生，必须以当前浏览器里的 GitHub / Cloudflare 登录身份为准，发现还是上一位学生的账号就先停止并让我切换。

确认账号无误后，再带我打开官方 Deploy to Cloudflare：
https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare

部署时请自动完成你能够完成的检查、构建、迁移和验证。只有 GitHub / Cloudflare 官方授权、一次性部署口令、管理员密码、系统恢复码需要我本人操作时再叫我。

不要向我索取或让我发送：GitHub 密码、Cloudflare 密码、管理员密码、INITIAL_ADMIN_CODE、系统恢复码、浏览器 Cookie、长期 API Token。

首次部署完成后继续带我进入 /admin：用一次性部署口令创建管理员密码、保存系统恢复码，然后检查图片上传、MP4 播放、草稿预览、正式发布、二维码访问、网站空间、使用教程和程序升级中心是否正常。
```

### 2.6 发出引导语以后，先等 GPT 核对账号

GPT 的第一阶段应该做这些事：

- 问清楚当前是哪个学生、要部署第几个网站；
- 确认当前 GitHub 登录身份；
- 确认当前 Cloudflare 登录身份；
- 判断是否已经有同类网站；
- 为新站规划不会重名的仓库、Worker、D1 和 KV 名称；
- 然后再让你打开 Cloudflare 官方部署入口。

如果 GPT 一上来就让你直接部署，却没有核对账号，先回复：

```text
先不要部署。请先确认当前浏览器里的 GitHub 和 Cloudflare 登录账号，以及这是该账号里的第几个网站。
```

### 2.7 截图时遮住秘密

可以发：

- GitHub 或 Cloudflare 页面整体截图；
- 项目名称、仓库名称、Worker 名称；
- 构建失败的红色错误；
- 页面按钮和字段位置。

必须遮住或不发送：

- GitHub 密码；
- Cloudflare 密码；
- 管理员密码；
- `INITIAL_ADMIN_CODE`；
- 系统恢复码；
- API Token；
- 浏览器 Cookie。

### 2.8 什么时候才可以点击部署链接

只有在 GPT 已经明确确认：

1. GitHub 账号正确；
2. Cloudflare 账号正确；
3. 新站名称不会覆盖旧站；
4. 新站会使用独立 D1 和 `MEDIA_KV`；

之后，再进入下一步。

## 3. Cloudflare 一键部署：逐步操作

> Cloudflare 的界面可能调整。某个字段已经自动填写时保留默认值；某个资源已经自动创建时，不要再手工创建第二份。

### 3.1 再检查一次账号

点击部署按钮前，确认：

- GitHub 页面右上角是自己的头像和用户名；
- Cloudflare 控制台是自己的账号；
- 浏览器没有残留上一位学生的登录状态；
- 已经知道这是第一个、第二个还是第三个网站。

账号不对就先退出切换。不要抱着“部署完再改”的想法，因为仓库、Worker、D1 和 KV 会直接建到错误账号里。

### 3.2 打开官方部署入口

**[点击这里进入 Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare)**

只使用上面的官方入口。不要自己先去 Cloudflare 手工创建 Worker、D1 或 KV。

### 3.3 GitHub 登录或授权

第一次使用时可能出现 GitHub 页面：

1. 确认页面显示的是自己的 GitHub 用户名。
2. 未登录时，使用原来的 GitHub 登录方式登录。
3. 出现 **Authorize Cloudflare** 时点击授权。
4. 授权对象必须是当前学生自己的 GitHub 账号。
5. 如果看到上一位学生的用户名，立即取消，不要继续。

### 3.4 Cloudflare 登录

Cloudflare 可能要求重新登录。必须使用创建账号时的原始方式：

- 当初用 Google 创建，就点 Google；
- 当初用 GitHub 创建，就点 GitHub；
- 当初用 Apple 创建，就点 Apple；
- 当初用邮箱密码创建，才填写邮箱和密码。

出现：

```text
Your account uses a different login provider
```

说明登录方式选错，不是网站坏了。返回并使用最初创建账号时的登录方式。

### 3.5 选择 Cloudflare 账号

一个登录身份下面可能有多个 Cloudflare 账号。必须选择当前学生自己的账号，不要选择老师、公司、同学或上一位学生的账号。

### 3.6 “Set up your application” 页面怎么填

页面出现相应字段时，按下表处理：

| 页面字段 | 正确做法 |
|---|---|
| Git account | 确认是当前学生自己的 GitHub。 |
| Project name | 必须唯一。推荐 `student-portfolio-姓名拼音-01`。只用小写英文字母、数字和短横线，不用中文、空格或下划线。 |
| Repository | 让 Cloudflare 创建新仓库。已有同名仓库时改成 `-02`、`-03`，不要覆盖。 |
| Create private Git repository | 界面提供时建议勾选，除非确实需要公开学生自己的源码。 |
| Production branch | 保持 `main`。 |
| Build command | 自动出现时保持 `npm run build`。 |
| Deploy command | 自动出现时保持 `npm run deploy`。 |
| Root directory | 保持 `/`、留空或使用页面默认值。 |
| D1 database / DB | 优先自动创建；要求选择时选 **Create new**，名称可用 `项目名-db`。不能选择其他网站已有数据库。 |
| KV namespace / MEDIA_KV | 优先自动创建；要求选择时选 **Create new**，名称可用 `项目名-media`。不能选择其他网站已有 KV。 |
| INITIAL_ADMIN_CODE | 选择 Secret / 加密变量，填写至少 16 位且同时包含英文字母和数字的一次性部署口令。只在 Cloudflare 官方页面输入。 |

同一账号第二个网站示例：

```text
项目：student-portfolio-linyuan-02
仓库：student-portfolio-linyuan-02
D1：student-portfolio-linyuan-02-db
KV：student-portfolio-linyuan-02-media
```

### 3.7 确认资源隔离

在点击部署前，再确认：

- 新站的 D1 绑定名是 `DB`；
- 新站的 KV 绑定名是 `MEDIA_KV`；
- 两者都是新站独立资源；
- 没有选择旧网站正在使用的 D1 或 KV。

第二个网站复用第一个网站的 D1/KV，会造成作品、管理员、图片或视频串站，这是严重错误。

### 3.8 设置一次性部署口令

`INITIAL_ADMIN_CODE` 的规则：

- 至少 16 位；
- 同时包含英文字母和数字；
- 不要使用姓名、生日或手机号；
- 只在 Cloudflare Secret 输入框填写；
- 不要发给 GPT、老师、同学或群聊；
- 第一次初始化管理员后，它不再作为日常登录密码使用。

### 3.9 点击 Deploy / Create and deploy

部署通常会依次执行：

1. 创建或复制 GitHub 仓库；
2. 安装依赖；
3. 构建网站；
4. 创建或绑定 D1；
5. 创建或绑定 `MEDIA_KV`；
6. 应用数据库迁移；
7. 发布 Worker。

等待页面明确显示成功。不要在构建途中关闭页面，也不要因为等待几十秒就连续点击部署按钮。

### 3.10 部署成功后保存四项信息

- GitHub 仓库地址；
- Cloudflare Worker 名称；
- `workers.dev` 前台地址；
- 后台地址：在前台地址后加 `/admin`。

示例：

```text
前台：https://你的项目名.你的子域.workers.dev/
后台：https://你的项目名.你的子域.workers.dev/admin
```

### 3.11 部署失败怎么办

- 不要立刻创建第二个项目。
- 打开当前失败构建的日志。
- 滚到最底部，找到最后一段红色错误。
- 截图时遮住所有秘密信息。
- 把错误交给 GPT，让它修复当前项目。
- 如果 Worker、D1 或 KV 已经创建，优先继续使用它们，不要重复创建同名或第二套资源。

## 4. 第一次进入后台

1. 打开部署后的后台地址 `/admin`。
2. 输入部署时设置的 `INITIAL_ADMIN_CODE`。
3. 创建管理员密码：10 至 128 位，至少包含文字和数字。
4. 再输入一次管理员密码。
5. 点击创建管理员。
6. 系统只显示一次恢复码，立即下载并离线保存。
7. 确认恢复码已保存后，再进入后台。

管理员密码、一次性部署口令和恢复码都不要发给 GPT。

## 5. 后台每一栏怎么用

### 概览

- 修改浏览器标签和网站名称；
- 设置普通公开访问或二维码限制访问；
- 查看作品、分类、媒体和修订数量；
- 查看已发布状态；
- 查看网站空间；
- 查看程序版本和升级中心。

### 联系

- 修改邮箱、电话、眉题、主标题和说明；
- 上传 1:1 联系图片；
- 选择资料在左或图片在左；
- 在真实画布中拖动文字位置；
- 双击画布文字可以直接修改。

### 首图与文字

- 上传一张或多张首页首图；
- 调整首图顺序、复制或删除；
- 选择纯图片、系统排版或自由排版；
- 编辑姓名、职业标题、求职方向、个人定位和状态短句；
- 选择页面主题；
- 上传自定义字体；
- 调整作品区大标题。

### 作品分类

- 新建和删除分类；
- 修改分类名称、颜色和顺序；
- 选择系统过渡条或上传 8:1 自定义过渡图；
- 有作品仍属于该分类时，必须先移动作品再删除分类。

### 作品

- 新建作品并选择分类；
- 编辑作品名称、年份、简介、难点和解决思路；
- 上传 16:9 项目封面；
- 上传成稿 MP4，视频时长自动读取；没有视频时显示 `00:00`；
- 设置视频水印；
- 设置封面文字是否显示、悬浮显示或常驻；
- 在真实封面中拖动标题、简介和项目信息；
- 添加文字、图文混排、图片组、通栏图片内容块；
- 图片组最多四张，可选择横图或竖图。

### 发布

- 检查首图、封面、视频等必要媒体；
- 必要内容缺失时不能正式发布；
- 发布会生成公开快照；
- 发布后继续编辑草稿，不会自动改变访客正在看的版本。

### 记录

- 查看最近访问；
- 查看展开作品、播放请求和播放错误；
- 查看后台保存、发布和上传操作；
- 网络标识已经做不可逆处理。

### 使用教程

- 登录后台后，右上角点击 **“使用教程”**；
- 打开后台版操作说明，并可跳转到 GitHub 完整指南；
- 教程入口只在管理员登录后显示。

### 程序升级

- 登录后台后，右上角点击 **“程序升级”**，页面会自动跳到升级中心；
- 也可以进入 **“概览”**，在 **“网站空间”** 下方找到 **“程序升级中心”**；
- 点击 **“复制给 GPT 的升级指令”** 开始升级。

## 6. 图片与视频建议尺寸

图片支持 JPG、PNG、WebP、AVIF。系统会尝试转为 WebP，并把最长边控制在 2560 像素以内；优化后单张仍不能超过 8 MiB。

| 使用位置 | 裁切比例 | 建议尺寸 | 构图建议 |
|---|---:|---:|---|
| 首页首图 | 自由裁切 | 2560 × 1440 | 主体放在中间 60%，四周留裁切空间。 |
| 联系图片 | 1:1 | 1600 × 1600 | 主体居中，不要贴边。 |
| 分类过渡图 | 8:1 | 2560 × 320 | 使用横向纹理、环境或大留白。 |
| 项目封面 | 16:9 | 1920 × 1080 或 2560 × 1440 | 文字和主体不要贴边。 |
| 图文混排图片 | 4:3 | 2000 × 1500 | 左右保留呼吸空间。 |
| 图片组竖图 | 3:4 | 1500 × 2000 | 同组保持色调和主体比例一致。 |
| 图片组横图 | 4:3 | 2000 × 1500 | 同组保持视觉风格一致。 |
| 通栏图片 | 16:9 | 1920 × 1080 或 2560 × 1440 | 关键内容放安全区。 |
| 成稿视频 | 推荐 16:9 | 1920 × 1080 | MP4、H.264 / AAC、单个不超过 50 MB。 |

### 视频压缩参考

- 30 秒：约 8–10 Mbps；
- 60 秒：约 5–6 Mbps；
- 120 秒：约 2.5–3 Mbps；
- 推荐 24、25 或 30 fps；
- 不必导出 4K；
- 最终以导出文件实际小于 50 MB 为准。

网站应用空间上限为 800 MiB，达到约 700 MiB 时预警。

---

## 7. 裁切、排版与预览

- 图片上传后先使用默认裁切。
- 平时预览不显示裁切虚框。
- 点击“调整”后才显示裁切框。
- 调整完成后点击“确认裁切”，虚框随即消失。
- 项目封面、图文、图片组和通栏图按各自固定比例裁切。
- 首图可以自由裁切。
- 文字可在真实画布中拖动。
- 双击文字可直接修改。
- 封面和联系模块的排版调整会即时反映在真实预览中。

---

## 8. 保存草稿与正式发布

正确流程：

**编辑 → 保存草稿 → 快速预览 → 正式发布**

- **保存草稿**：只更新后台草稿，公开前台不变。
- **快速预览**：打开管理员当前草稿版本。
- **正式发布**：生成新的公开快照，访客才会看到变化。
- 左下角显示“有未保存修改”时，离开前必须保存。
- 快速预览被浏览器拦截时，需要允许当前站点打开新窗口。

---

## 9. 二维码访问

- 关闭“限制访问”时，普通前台链接可以直接打开。
- 开启后，可为不同对象生成独立二维码。
- 每个二维码可设置名称、最多使用次数和到期时间。
- 可暂停、恢复或删除二维码。
- 达到次数、过期或暂停后，二维码自动失效。
- 不同二维码的访问记录分开统计。

---

## 10. 密码、12 小时登录与恢复码

- 输入正确管理员密码后，这台浏览器会保持登录 12 小时。
- 12 小时内再次从前台点“管理”，通常会直接进入后台。
- 点击“安全退出”后，当前登录状态立即失效。
- 连续输错 5 次密码，会锁定 15 分钟。
- 忘记密码时，使用最新系统恢复码重置。
- 恢复码每次只能使用一次，使用后旧码作废并生成新码。
- 密码和最新恢复码同时丢失时，网站无法自行找回。

## 11. 一个 GPT 帮不同学生部署

同一个 GPT 账号可以帮助不同学生，但每次必须重新确认：

1. 当前正在帮助哪位学生；
2. 浏览器当前登录的是谁的 GitHub；
3. 浏览器当前登录的是谁的 Cloudflare；
4. 当前要部署哪个网站；
5. 是否仍残留上一位学生的登录状态。

GPT 账号只是助手身份，不决定网站归属。网站属于实际授权的 GitHub 和 Cloudflare 账号。

---

## 12. 同一个托管账号部署多个网站

一个 GitHub / Cloudflare 账号可以部署多个网站，但每个网站必须独立拥有：

- GitHub 仓库；
- Worker；
- D1 数据库；
- `MEDIA_KV`；
- `workers.dev` 地址；
- 管理员密码；
- 系统恢复码。

推荐命名：

```text
student-portfolio-name-01
student-portfolio-name-02
student-portfolio-name-03
```

第二个网站绝不能复用第一个网站的 D1 或 KV，否则内容和媒体会串站。

## 13. 程序升级

### 升级按钮在哪里

登录后台后有两个入口：

1. **后台右上角“程序升级”**：点击后自动进入“概览”并滚动到升级中心。
2. **概览 → 网站空间 → 程序升级中心**：点击“复制给 GPT 的升级指令”。

升级不是重新部署新网站。它只更新程序代码和增量数据库迁移。

必须保留：

- 当前 Worker 和 `workers.dev` 地址；
- D1 资源及全部数据；
- `MEDIA_KV` 及全部图片、视频；
- Cloudflare Secrets；
- 管理员密码、会话和恢复状态；
- 草稿和已发布内容；
- 二维码、访问记录和管理记录。

复制给 GPT：

```text
请把我的“学生作品展示”网站升级到模板最新版本。先确认当前要升级的具体网站、Worker、D1 DB 和 MEDIA_KV，再读取 README.md、AGENTS.md、deployment/agent-manifest.json 和 deployment/template-version.json。只更新程序代码和增量数据库迁移，必须保留当前网站地址、D1、MEDIA_KV、管理员账号、Secrets、图片、视频、草稿、已发布内容、二维码和访问记录。不要创建新的 Worker、D1 或 KV，也不要覆盖现有资源 ID。升级完成后检查后台登录、图片、视频、草稿预览、正式发布、网站空间、使用教程和程序升级按钮。
```

## 14. 常见问题

### 点“管理”为什么不要求密码

通常是这台浏览器仍在 12 小时登录期内。点击“安全退出”后再进入即可验证密码门禁。

### Cloudflare 报 different login provider

登录方式选错。改用创建 Cloudflare 账号时的原始方式。

### 同名资源已存在

新网站名称改成 `-02` 或 `-03`。不要覆盖旧站，也不要复用旧站 D1/KV。

### 部署失败

查看当前构建日志最底部的红色错误，让 GPT 修复当前项目。不要立刻再建第二套网站。

### 图片上传失败

检查格式和大小，建议先把最长边压到 2560 像素以内。

### 视频上传失败

确认是 H.264 / AAC 编码的 MP4，且文件小于 50 MB。

### 快速预览打不开

允许当前站点打开新窗口。

### 保存后前台没变化

保存草稿不等于发布。进入“发布”完成正式发布，再刷新前台。

### 看不到“使用教程”或“程序升级”

先确认已经成功登录后台，然后按 `Ctrl + F5` 强制刷新。两个按钮都只在管理员后台显示。
