# 学生作品展示｜部署与后台使用指南

> **部署前入口：本 GitHub 页面。**  
> **部署后入口：登录自己网站的 `/admin`，点击右上角“使用教程”。**
>
> GitHub 承担部署前的公开说明；每位学生部署成功后，由自己的 Cloudflare 账号承载前台和后台访问。模板不提供公共 `/guide` 页面。

---

## 一页看懂整个流程

**打开本指南 → 打开 GPT → 核对 GitHub / Cloudflare 账号 → 官方一键部署 → 创建管理员 → 编辑内容 → 快速预览 → 正式发布。**

| 入口 | 用途 |
|---|---|
| GitHub 本页 | 部署前的中央指南与官方部署入口 |
| 学生网站 `/` | 对外展示的作品集前台 |
| 学生网站 `/admin` | 管理员后台，使用密码登录 |
| 后台“使用教程” | 登录后打开与本页同版的教程 |
| 后台“程序升级” | 定位升级中心并复制升级指令 |

### 安全边界

| 可以发给 GPT | 只在官方页面或网站后台输入 |
|---|---|
| 页面整体截图、按钮位置、项目名、仓库名、Worker 名、构建错误 | GitHub 密码、Cloudflare 密码、管理员密码、`INITIAL_ADMIN_CODE`、系统恢复码、API Token、浏览器 Cookie |

## 1. 部署前准备

### 1.1 账号与设备

准备以下内容后再开始：

- 一个可正常使用的 ChatGPT 账号；
- 一个可正常登录的 GitHub 账号；
- 一个可正常登录的 Cloudflare 账号；
- 一个能接收验证码的邮箱；
- 一台电脑，推荐 Chrome 或 Edge；
- 手机放在旁边，用于邮箱验证码或二步验证。

Google / Gmail 不是硬性要求。GitHub 和 Cloudflare 可以使用 Google、GitHub、Apple 或邮箱密码登录，关键是记清自己最初选择的登录方式。

建议先记录：

| 项目 | 自己填写 |
|---|---|
| GitHub 用户名 |  |
| GitHub 登录方式 | Google / 邮箱密码 / 其他 |
| Cloudflare 登录邮箱 |  |
| Cloudflare 登录方式 | Google / GitHub / Apple / 邮箱密码 |
| 这是该账号的第几个网站 | 第 1 / 2 / 3 个 |

### 1.2 部署不需要额外密钥

正常流程无需提前创建：

- OpenAI API Key；
- Codex API Key；
- Cloudflare API Token；
- GitHub Personal Access Token；
- 其他长期密钥。

### 1.3 素材建议提前整理

- 姓名；
- 职业标题和求职方向；
- 一句个人定位；
- 邮箱和电话；
- 首页首图；
- 项目封面；
- 项目简介、项目难点、解决思路；
- 项目过程图片；
- H.264 / AAC 编码的 MP4 成稿视频。

## 2. 先打开 GPT：每一步点哪里

### 2.1 打开 ChatGPT

1. 在电脑浏览器登录自己的 ChatGPT。
2. 点击“新建对话”。
3. 页面有“工作”模式时优先选择“工作”；没有时使用普通对话。
4. 后续 GPT 需要 Codex 检查仓库或修复构建时，可以允许相应操作。

### 2.2 选择模型和思考程度

- 最低模型：**GPT-5.6 Sol**；
- 正常部署：思考程度选择 **“高”**；
- 资源绑定、数据库迁移、账号串号、版本冲突、复杂构建故障或升级：改为 **“超高”**。

账号中需要能选择 GPT-5.6 Sol 后再进行正式部署。

### 2.3 完整复制部署引导语

```text
我要部署“学生作品展示”网站。请全程一步一步带我完成，一次只让我做一个主要动作。

开始前请先确认：
1. 我使用的模型至少是 GPT-5.6 Sol，思考程度为“高”；复杂故障时提醒我改成“超高”。
2. 当前浏览器实际登录的是哪一个 GitHub 账号、哪一个 Cloudflare 账号。
3. 这是这个 GitHub / Cloudflare 账号里的第几个学生作品网站。
4. 如果账号里已有其他网站，请为本次网站规划新的仓库、Worker、D1 和 MEDIA_KV，保持资源完全独立。
5. 如果同一个 GPT 正在帮助不同学生，请以当前浏览器里的 GitHub / Cloudflare 登录身份为准。

在要求我授权前，先分别对当前 GitHub 和 Cloudflare 连接执行一次无害的只读检查。只读检查成功就复用现有连接，不要再次打开授权页面。只有官方连接明确返回 Connect、Reconnect、授权已过期或权限不足时，才让我在官方页面授权一次。授权后重新执行同一只读检查，并从刚才中断的步骤继续；不要重新开始部署，不要重复创建仓库、Worker、D1 或 MEDIA_KV。若授权页面连续再次出现，立即停止并核对账号、目标站点和已经创建的资源。

账号和命名确认完成后，再带我打开官方 Deploy to Cloudflare：
https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare

请自动完成能够完成的检查、构建、迁移和验证。GitHub / Cloudflare 官方授权、一次性部署口令、管理员密码和系统恢复码由我本人操作。

以下信息始终由我本人在官方页面输入，不进入聊天：GitHub 密码、Cloudflare 密码、管理员密码、INITIAL_ADMIN_CODE、系统恢复码、浏览器 Cookie、长期 API Token。

首次部署完成后继续带我进入 /admin：使用一次性部署口令创建管理员密码、保存系统恢复码，并检查图片上传、MP4 播放、草稿预览、正式发布、二维码访问、网站空间、使用教程和程序升级中心。
```

### 2.4 先完成账号核对

GPT 应先确认：

- 当前正在帮助哪位学生；
- GitHub 登录身份；
- Cloudflare 登录身份；
- 这是第几个网站；
- 新站的仓库、Worker、D1、KV 命名；
- 新站资源是否与旧站隔离。

如果 GPT 尚未核对账号就进入部署，发送：

```text
请先确认当前浏览器里的 GitHub 和 Cloudflare 登录账号，并确认这是该账号里的第几个网站，再继续部署。
```

完成账号核对后再进入 Cloudflare。

## 3. Cloudflare 一键部署：逐步操作

Cloudflare 的页面可能随版本调整。页面已经自动填写的内容优先保留；系统已经自动创建的资源直接沿用本次部署结果。

### 3.1 打开官方入口

**[进入 Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare)**

该入口负责复制模板、创建仓库、配置 Worker，并准备本网站需要的 D1 与 `MEDIA_KV`。

本模板按 Cloudflare 免费资源组合设计，媒体保存在 `MEDIA_KV`，不需要启用 R2。页面如果要求开通 R2、付费套餐或订阅，先停止操作并把当前完整页面截图交给 GPT 核对，不要直接确认付费。

### 3.2 GitHub 登录与授权

1. GPT 先使用 GitHub 官方连接执行一次无害的只读检查，例如读取当前账号可访问的仓库。
2. 检查成功：说明连接仍然有效，直接复用，不再打开登录或授权页面。
3. 只有官方连接明确显示 **Connect**、**Reconnect**、授权过期或权限不足时，才进入授权。
4. 授权前核对页面中的 GitHub 用户名；未登录时使用自己原来的登录方式。
5. 出现 **Authorize Cloudflare** 时，确认账号后只授权一次。
6. 授权完成后重新执行同一个只读检查，确认身份正确，再从中断步骤继续。
7. 不要重新开始整个部署，不要重复创建仓库、Worker、D1 或 `MEDIA_KV`。
8. 如果授权页面再次连续出现，立即停止并核对账号、目标网站和已经创建的资源。

### 3.3 Cloudflare 登录

GPT 同样应先对 Cloudflare 官方连接做只读检查；检查成功就复用当前连接，只有明确要求连接或重新连接时才打开登录页。授权完成后回到原步骤继续，不重新执行已经完成的资源创建。

使用创建 Cloudflare 账号时的原始方式：

- Google 创建：选择 Google；
- GitHub 创建：选择 GitHub；
- Apple 创建：选择 Apple；
- 邮箱密码创建：填写邮箱和密码。

出现下面提示时，返回并切换为最初的登录方式：

```text
Your account uses a different login provider
```

### 3.4 选择 Cloudflare 账号

一个登录身份可能包含多个 Cloudflare 账号。请选择当前学生自己的账号，并再次确认这是第几个作品网站。

### 3.5 “Set up your application” 页面怎么填

| 页面字段 | 处理方式 |
|---|---|
| Git account | 当前学生自己的 GitHub |
| Project name | 使用唯一名称，推荐 `student-portfolio-姓名拼音-01` |
| Repository | 创建新仓库；同名时使用 `-02`、`-03` |
| Create private Git repository | 页面提供时可勾选，让学生源码保持私有 |
| Production branch | 保持 `main` |
| Build command | 保留自动值，通常为 `npm run build` |
| Deploy command | 保留自动值，通常为 `npm run deploy` |
| Root directory | 保持 `/`、留空或保留默认值 |
| D1 database / DB | 优先自动创建；需要选择时选 **Create new**，名称可用 `项目名-db` |
| KV namespace / MEDIA_KV | 优先自动创建；需要选择时选 **Create new**，名称可用 `项目名-media` |
| INITIAL_ADMIN_CODE | 使用 Secret / 加密变量，至少 16 位，并同时包含英文字母和数字 |

命名只使用小写英文字母、数字和短横线。

第二个网站示例：

```text
项目：student-portfolio-linyuan-02
仓库：student-portfolio-linyuan-02
D1：student-portfolio-linyuan-02-db
KV：student-portfolio-linyuan-02-media
```

### 3.6 确认资源隔离

每个网站独立拥有：

- Worker；
- D1，绑定名为 `DB`；
- KV，绑定名为 `MEDIA_KV`；
- 管理员密码和系统恢复码；
- 图片、视频、草稿和发布内容。

这一检查能避免不同网站之间出现内容串联。

### 3.7 设置一次性部署口令

`INITIAL_ADMIN_CODE`：

- 至少 16 位；
- 同时包含英文字母和数字；
- 建议使用随机组合；
- 填写在 Cloudflare Secret 输入框；
- 第一次创建管理员后，日常登录改用管理员密码。

### 3.8 点击 Deploy / Create and deploy

部署通常包含：

1. 创建或复制 GitHub 仓库；
2. 安装依赖；
3. 构建网站；
4. 创建或绑定 D1；
5. 创建或绑定 `MEDIA_KV`；
6. 应用数据库迁移；
7. 发布 Worker。

保持页面打开，等待明确的成功状态。

### 3.9 保存部署结果

记录以下信息：

- GitHub 仓库地址；
- Cloudflare Worker 名称；
- 前台 `workers.dev` 地址；
- 后台地址：前台地址后加 `/admin`。

```text
前台：https://你的项目名.你的子域.workers.dev/
后台：https://你的项目名.你的子域.workers.dev/admin
```

### 3.10 构建出现错误时

1. 打开当前项目的构建日志；
2. 滚动到最底部；
3. 截取最后一段红色错误并遮住秘密信息；
4. 让 GPT 修复当前项目；
5. 已经创建的 Worker、D1、KV 优先沿用，修复后重新部署。

## 4. 第一次进入后台

1. 打开部署后的 `/admin`。
2. 输入部署时设置的 `INITIAL_ADMIN_CODE`。
3. 创建管理员密码：10 至 128 位，至少包含文字和数字。
4. 再输入一次管理员密码。
5. 点击“创建管理员”。
6. 下载系统恢复码并离线保存。
7. 确认恢复码已保存后进入后台。

一次性部署口令只负责首次初始化；之后日常登录使用管理员密码。

## 5. 后台每一栏怎么用

### 概览

- 修改浏览器标签与网站名称；
- 设置普通公开访问或二维码限制访问；
- 查看作品、分类、媒体与修订数量；
- 查看发布状态；
- 查看网站空间；
- 查看程序版本与升级中心。

### 联系

- 修改邮箱、电话、眉题、主标题和说明；
- 上传 1:1 联系图片；
- 选择资料在左或图片在左；
- 在真实画布中拖动文字；
- 双击画布文字直接修改内容。

### 首图与文字

- 上传一张或多张首页首图；
- 调整顺序、复制或删除；
- 选择纯图片、系统排版或自由排版；
- 编辑姓名、职业标题、求职方向、个人定位和状态短句；
- 选择页面主题；
- 上传自定义字体；
- 调整作品区大标题。

### 作品分类

- 新建分类；
- 修改名称、颜色和顺序；
- 使用系统过渡条或上传 8:1 自定义过渡图；
- 删除分类前，先把该分类中的作品移动到其他分类。

### 作品

- 新建作品并选择分类；
- 编辑名称、年份、简介、难点和解决思路；
- 上传 16:9 项目封面；
- 上传成稿 MP4，视频时长自动读取；没有视频时显示 `00:00`；
- 设置视频水印；
- 设置封面文字显示方式；
- 在真实封面中拖动标题、简介和项目信息，并分别检查“桌面 16:9”和“手机 4:5”；
- 添加文字、图文混排、图片组、通栏图片；
- 图片组最多四张，可选择横图或竖图。

### 发布

- 检查首图、封面、视频等必要媒体；
- 完成必要内容后生成公开快照；
- 发布后继续编辑草稿，访客仍看到上一次公开版本，直到再次发布。

### 记录

- 查看最近访问；
- 查看展开作品、播放请求和播放错误；
- 查看后台保存、发布和上传操作；
- 网络标识采用不可逆处理。

### 使用教程

登录后台后，右上角点击 **“使用教程”**，可打开本指南的后台版。

### 程序升级

登录后台后，右上角点击 **“程序升级”**，系统会进入概览并定位到升级中心。

## 6. 图片与视频建议尺寸

图片支持 JPG、PNG、WebP、AVIF。系统会尝试转为 WebP，并把最长边控制在 2560 像素以内；优化后单张上限为 8 MiB。

| 使用位置 | 裁切比例 | 建议尺寸 | 构图建议 |
|---|---:|---:|---|
| 首页首图 | 自由裁切 | 2560 × 1440 | 主体放在中间 60%，四周预留裁切空间 |
| 联系图片 | 1:1 | 1600 × 1600 | 主体居中，四周留边 |
| 分类过渡图 | 8:1 | 2560 × 320 | 适合横向纹理、环境或大留白 |
| 项目封面 | 16:9 | 1920 × 1080 或 2560 × 1440 | 重要主体和文字放在安全区 |
| 图文混排图片 | 4:3 | 2000 × 1500 | 左右保留呼吸空间 |
| 图片组竖图 | 3:4 | 1500 × 2000 | 同组保持色调和主体比例一致 |
| 图片组横图 | 4:3 | 2000 × 1500 | 同组保持视觉风格一致 |
| 通栏图片 | 16:9 | 1920 × 1080 或 2560 × 1440 | 关键内容放在中央安全区 |
| 成稿视频 | 推荐 16:9 | 1920 × 1080 | MP4、H.264 / AAC、单个不超过 50 MB |

### 视频压缩参考

- 30 秒：约 8–10 Mbps；
- 60 秒：约 5–6 Mbps；
- 120 秒：约 2.5–3 Mbps；
- 推荐 24、25 或 30 fps；
- 1080p 足够用于作品展示；
- 最终以导出文件实际小于 50 MB 为准。

网站应用空间上限为 800 MiB，达到约 700 MiB 时预警。

## 7. 裁切、排版与预览

- 上传图片后先使用默认裁切；
- 点击“调整”后显示裁切框；
- 调整完成后点击“确认裁切”，裁切框随即收起；
- 项目封面、图文、图片组和通栏图使用各自固定比例；
- 首图支持自由裁切；
- 文字可以在真实画布中拖动；
- 双击文字可直接修改；
- 项目封面排版时，先看“桌面 16:9”，再切换“手机 4:5”，确认标题字号、宽度和换行都正确；
- 封面和联系模块的设置会即时显示在真实预览中；
- 图片显示“媒体已上传，等待草稿保存”时，本地预览仍会保留；先保存草稿，再点“重新检查”。

## 8. 保存草稿与正式发布

**编辑 → 保存草稿 → 快速预览 → 正式发布**

- **保存草稿**：更新后台草稿，公开前台保持当前版本；
- **快速预览**：查看管理员当前草稿；
- **正式发布**：生成新的公开快照，访客看到新版本；
- 每次上传或替换图片后先保存草稿，再切换作品或后台栏目；
- 左下角显示“有未保存修改”时，保存后再离开；
- 浏览器拦截快速预览时，为当前站点允许弹出窗口。

---

## 9. 二维码访问

- 关闭限制访问时，普通前台链接可直接打开；
- 开启后，可为不同对象生成独立二维码；
- 每个二维码可设置名称、最多使用次数和到期时间；
- 支持暂停、恢复与删除；
- 达到次数、过期或暂停后，二维码自动失效；
- 不同二维码的访问记录分开统计。

---

## 10. 密码、12 小时登录与恢复码

- 输入正确管理员密码后，这台浏览器保持登录 12 小时；
- 12 小时内再次点“管理”，通常直接进入后台；
- 点击“安全退出”后，当前会话立即结束；
- 连续输错 5 次密码，系统锁定 15 分钟；
- 忘记密码时，使用最新系统恢复码重置；
- 恢复码每次使用后自动轮换，新码需要重新保存；
- 管理员密码与最新恢复码分开离线保存。

## 11. 一个 GPT 帮不同学生部署

同一个 GPT 账号可以帮助不同学生。每次部署重新确认：

1. 当前学生；
2. GitHub 登录身份；
3. Cloudflare 登录身份；
4. 本次目标网站；
5. 当前账号已有的网站数量；
6. 新站的独立资源名称。

GPT 是操作助手；网站归属由实际授权的 GitHub 和 Cloudflare 账号决定。

## 12. 同一个托管账号部署多个网站

一个 GitHub / Cloudflare 账号可以部署多个网站。每个网站分别拥有：

- GitHub 仓库；
- Worker；
- D1 数据库；
- `MEDIA_KV`；
- `workers.dev` 地址；
- 管理员密码；
- 系统恢复码。

推荐命名：

```text
student-portfolio-name-01
student-portfolio-name-02
student-portfolio-name-03
```

资源独立后，各网站的内容、管理员和媒体互不影响。

## 13. 程序升级

### 升级按钮在哪里

登录后台后有两个入口：

1. **右上角“程序升级”**：点击后进入概览并定位升级中心；
2. **概览 → 网站空间 → 程序升级中心**：点击“复制给 GPT 的升级指令”。

每次登录后台时，网站会自动检查主模板版本。发现新版本后，右上角 **“程序升级”会显示小红点**，升级中心会显示当前版本、最新版本和更新内容。该提醒只在网站后台内显示，不是短信、邮件或手机系统推送。

升级沿用现有 Worker、D1 与 `MEDIA_KV`，只更新程序代码和增量数据库迁移。

升级时保留：

- 当前 Worker 与 `workers.dev` 地址；
- D1 及全部数据；
- `MEDIA_KV` 及全部图片、视频；
- Cloudflare Secrets；
- 管理员账号、密码验证与恢复状态；
- 草稿和已发布内容；
- 二维码、访问记录和管理记录。

复制给 GPT：

```text
请把我的“学生作品展示”现有网站升级到模板最新版本。开始前先确认当前要升级的 GitHub 仓库、Cloudflare 账户、Worker、workers.dev 地址、D1 的 DB 绑定及资源 ID、MEDIA_KV 绑定及资源 ID，并读取 README.md、AGENTS.md、deployment/agent-manifest.json 和 deployment/template-version.json。

这是“升级现有站点”，不是新建站点。必须沿用现有 Worker、workers.dev 地址、D1、MEDIA_KV、Secrets 和运行变量；只允许更新程序代码及必要的增量数据库迁移。完整保留管理员账号与密码状态、会话与恢复状态、图片、字体、视频、草稿、已发布内容、二维码与访问凭证、访问统计和审计记录。不得创建第二套 Worker、D1、KV，不得创建或绑定 R2，不得把模板仓库中的任何资源 ID 覆盖到现有站点，也不得要求开通付费套餐、绑定付款方式或恢复邮件服务。发现上述情况、目标资源无法确认或迁移可能破坏正式数据时，立即停止并说明原因。

能够自动完成的检查、构建、测试、增量迁移、PR、合并和部署请自动完成。GitHub、Cloudflare 官方账号授权以及任何 INITIAL_ADMIN_CODE、管理员密码、系统恢复码、Token、Cookie 只由我本人在官方页面输入；不要在聊天中索取、展示或记录。

开始任何授权前，先对 GitHub 和 Cloudflare 官方连接执行无害的只读检查。检查成功就复用现有连接；只有明确显示 Connect、Reconnect、授权过期或权限不足时才授权一次。授权后重新执行同一检查并从中断步骤继续，不要重新开始升级，也不要重复创建或绑定任何资源。授权页面连续再次出现时，立即停止并核对账号、目标站点和现有资源。

升级完成后验证：Cloudflare 生产部署成功且 Worker、D1、MEDIA_KV、Secrets 未被替换；后台登录、退出、12 小时会话和恢复流程正常；图片上传、读取、删除正常；接近 50 MB 的 MP4 能按 4 MiB 分片上传，超过 50 MB 会被拒绝，播放与 Range 拖动正常；草稿、快速预览和正式发布相互隔离；二维码公开、限制、次数耗尽与过期规则正常；网站空间统计及 700 MiB 预警、800 MiB 上限正常；至少 10 个独立会话同时播放正常；桌面与手机封面、使用教程和程序升级按钮正常；大陆手机流量和常用宽带访问正常。最后报告版本、提交、生产部署结果、保留的资源及未能自动完成的检查。
```

## 14. 常见问题

### 为什么会直接进入后台

这台浏览器仍处于 12 小时登录期。点击“安全退出”后重新进入，可以验证密码门禁。

### Cloudflare 提示 different login provider

当前选择的登录方式与账号创建方式不同。返回并使用最初的 Google、GitHub、Apple 或邮箱密码方式。

### 项目名称已经存在

使用 `-02` 或 `-03` 创建新的唯一名称，并为新站配置独立 D1 与 KV。

### 构建没有成功

查看日志最底部的红色错误，让 GPT 修复当前项目，并沿用本次已经创建的资源。

### 图片上传没有完成

确认格式受支持，最长边建议控制在 2560 像素以内，优化后文件小于 8 MiB。

### 图片已经上传，但提示等待保存或预览暂时无法读取

先点击“保存草稿”，再点图片下方的“重新检查”或重新进入当前作品。不要重复上传同一张图；如果快速预览能打开而后台仍不显示，截取当前图片区和左下角状态提示交给 GPT。

### 视频上传没有完成

确认文件为 H.264 / AAC 编码的 MP4，且小于 50 MB。

### 快速预览没有打开

为当前站点允许弹出窗口，然后再次点击“快速预览”。

### 保存后前台仍是旧内容

保存草稿后进入“发布”，生成公开快照，再刷新前台。

### 使用教程或程序升级按钮未显示

确认已成功登录管理员后台，然后按 `Ctrl + F5` 强制刷新。

### 教程入口在哪里

部署前看 GitHub README；部署后从管理员后台右上角打开“使用教程”。
