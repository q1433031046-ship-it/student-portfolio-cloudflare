# 学生作品展示｜部署与后台使用傻瓜指南

> 这是本项目唯一面向学生的公开指南。**部署前只看 GitHub 这一页；部署完成后，登录自己的网站后台，点击右上角“使用教程”，可以打开同版教程。**
>
> 教程不再放在模板的公开 `/guide` 地址上，避免所有学生反复访问同一个 Cloudflare Worker。GitHub 负责部署前的公开说明；每个学生部署后由自己的 Cloudflare 账号承担自己网站的访问。

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare)

## 先看懂整个逻辑

- **GitHub 本页**：部署前的中央指南，公开可看，不消耗老师网站的 Cloudflare 请求。
- **学生自己的前台 `/`**：公开作品集，给招聘方、客户和同学查看。
- **学生自己的后台 `/admin`**：必须使用管理员密码，只有站点本人能编辑。
- **后台“使用教程”**：登录后台后才能打开，不再提供公共教程网页。
- **GPT 账号不等于托管账号**：同一个 GPT 可以帮助多人，但每次必须确认浏览器实际登录的是谁的 GitHub 和 Cloudflare。

正确顺序只有这一条：

**打开 GitHub 本指南 → 打开 GPT → GPT 核对账号 → 打开 Cloudflare 一键部署 → 创建管理员 → 编辑并发布。**

## 1. 部署前准备

### 必须准备

- 一个能正常使用的 ChatGPT 账号。
- 一个能正常登录的 GitHub 账号。
- 一个能正常登录的 Cloudflare 账号。
- 一个可以接收验证码的邮箱。
- 电脑浏览器，推荐 Chrome 或 Edge。
- 手机放在旁边，用于邮箱验证码或二步验证。

Google / Gmail **不是必须**。GitHub、Cloudflare 可以使用 Google、GitHub、Apple 或邮箱密码登录，但必须记清楚自己最初使用的是哪一种方式。

### 不需要准备

正常部署不需要提前创建以下内容：

- OpenAI API Key；
- Codex API Key；
- Cloudflare API Token；
- GitHub Personal Access Token；
- 任何长期密钥。

### 素材建议提前整理

- 姓名；
- 职业标题与求职方向；
- 一句个人定位；
- 邮箱与电话；
- 首页首图；
- 项目封面；
- 项目简介、难点、解决思路；
- 项目过程图；
- H.264 / AAC 编码的 MP4 成稿视频。

## 2. 先打开 GPT

### 模型要求

- **最低模型：GPT-5.6 Sol**
- **默认思考程度：高**
- 遇到部署失败、Cloudflare 资源绑定、数据库迁移、账号串号、版本冲突或程序升级时：改为 **超高**

界面里有“工作”模式时可以优先使用；没有也可以使用普通 ChatGPT 对话。关键不是界面名称，而是模型至少为 GPT-5.6 Sol，并让 GPT 一次只指导一个主要动作。

### 把下面整段复制给 GPT

```text
我要部署“学生作品展示”网站。请全程一步一步带我完成，一次只让我做一个主要动作，不要一次发很多步骤。

开始前请先确认：
1. 我使用的模型至少是 GPT-5.6 Sol，思考程度为“高”；复杂故障时提醒我改成“超高”。
2. 当前实际操作浏览器里登录的是哪一个 GitHub 账号、哪一个 Cloudflare 账号。
3. 这是这个 GitHub / Cloudflare 账号里的第几个学生作品网站；如果已经有其他网站，必须为这次网站使用新的仓库、Worker、D1 和 MEDIA_KV，绝不能复用旧网站的数据资源。
4. 如果同一个 GPT 账号正在帮助不同学生，必须以当前浏览器里的 GitHub / Cloudflare 登录身份为准，发现还是上一位学生的账号就先停止并让我切换。

确认账号无误后，再带我打开官方 Deploy to Cloudflare：
https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare

部署时请自动完成你能够完成的检查、构建、迁移和验证。只有 GitHub / Cloudflare 官方授权、一次性部署口令、管理员密码、系统恢复码需要我本人操作时再叫我。

不要向我索取或让我发送：GitHub 密码、Cloudflare 密码、管理员密码、INITIAL_ADMIN_CODE、系统恢复码、浏览器 Cookie、长期 API Token。

首次部署完成后继续带我进入 /admin：用一次性部署口令创建管理员密码、保存系统恢复码，然后检查图片上传、MP4 播放、草稿预览、正式发布、二维码访问、网站空间和程序升级中心是否正常。
```

## 3. Cloudflare 一键部署：逐步操作

> Cloudflare 的界面会不定期调整。某个字段如果已经自动填写，就保留默认值；某个资源如果已经自动创建，就不要再手工创建第二份。

### 3.1 GPT 先确认账号

在点击部署按钮之前，先让 GPT 带你确认：

- GitHub 页面右上角显示的是你自己的头像和用户名；
- Cloudflare 控制台登录的是你自己的账号；
- 浏览器里没有残留上一位学生的账号；
- 这是第一个网站，还是同一账号中的第二个、第三个网站。

账号不对就先退出再切换。不要抱着“部署完再改”的想法，因为部署到错误账号后，仓库、Worker、D1 和 KV 都会建错地方。

### 3.2 打开官方部署入口

点击：

**[Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/q1433031046-ship-it/student-portfolio-cloudflare)**

只使用上面的官方入口。不要自己先去 Cloudflare 手工创建 Worker、D1 或 KV。

### 3.3 GitHub 授权页面

第一次使用时，可能出现 GitHub 登录或授权页面：

1. 确认页面上显示的是自己的 GitHub 用户名。
2. 没登录就使用自己原来的 GitHub 登录方式登录。
3. 出现 **Authorize Cloudflare** 时，点击授权。
4. 授权对象必须是当前学生自己的 GitHub 账号。
5. 如果看到上一位学生的用户名，立即取消，不要继续。

### 3.4 Cloudflare 登录页面

Cloudflare 可能要求重新登录。必须使用创建 Cloudflare 账号时使用的原始方式：

- 当初使用 Google 创建，就点 Google；
- 当初使用 GitHub 创建，就点 GitHub；
- 当初使用 Apple 创建，就点 Apple；
- 当初使用邮箱密码创建，才填写邮箱和密码。

出现：

`Your account uses a different login provider`

不是网站坏了，而是登录方式选错了。返回并改用最初创建账号时的登录方式。

### 3.5 “Set up your application” 页面怎么填

Cloudflare 页面出现相应字段时，按下面处理：

| 页面字段 | 应该怎么做 |
|---|---|
| Git account | 确认是当前学生自己的 GitHub 账号。 |
| Project name | 必须唯一。推荐：`student-portfolio-姓名拼音-01`。只用小写英文字母、数字和短横线，不要使用中文、空格或下划线。 |
| Repository | 让 Cloudflare 创建新的仓库。已有同名仓库时，将末尾改成 `-02`、`-03`，不要覆盖旧仓库。 |
| Create private Git repository | 界面提供时建议勾选，除非确实需要公开源码。模板源仓库仍然可以公开。 |
| Production branch | 保持 `main`。 |
| Build command | 自动出现时保持 `npm run build`，不要随意修改。 |
| Deploy command | 自动出现时保持 `npm run deploy`，不要改成其他命令。 |
| Root directory | 保持 `/` 或留空，按页面默认值。 |
| D1 database / DB | 优先让系统自动创建。界面要求选择时选 **Create new**，名称可用 `项目名-db`。绝不能选择另一个网站已有的数据库。 |
| KV namespace / MEDIA_KV | 优先让系统自动创建。界面要求选择时选 **Create new**，名称可用 `项目名-media`。绝不能选择另一个网站已有的 KV。 |
| INITIAL_ADMIN_CODE | 选择 Secret/加密变量，填写至少 16 位、同时包含英文字母和数字的一次性部署口令。只在 Cloudflare 官方页面输入。 |

示例：第二个网站可以使用：

- 项目：`student-portfolio-linyuan-02`
- 仓库：`student-portfolio-linyuan-02`
- D1：`student-portfolio-linyuan-02-db`
- KV：`student-portfolio-linyuan-02-media`

### 3.6 点击 Deploy / Create and deploy

检查完成后点击页面底部的部署按钮。部署会经历：

1. 创建或复制 GitHub 仓库；
2. 安装依赖；
3. 构建网站；
4. 创建或绑定 D1；
5. 创建或绑定 `MEDIA_KV`；
6. 应用数据库迁移；
7. 发布 Worker。

等待页面明确显示成功，不要在构建途中关闭页面，也不要因为等了几十秒就重复点第二次。

### 3.7 部署成功后保存四项信息

- GitHub 仓库地址；
- Cloudflare Worker 名称；
- `workers.dev` 网站地址；
- 网站后台地址：在网站地址后加 `/admin`。

例：

```text
前台：https://你的项目名.你的子域.workers.dev/
后台：https://你的项目名.你的子域.workers.dev/admin
```

### 3.8 部署失败怎么办

- 不要立刻创建第二个项目。
- 打开失败构建的日志底部，找到最后一段红色错误。
- 截图时不要包含密码、一次性部署口令或恢复码。
- 把错误文字或安全截图发给 GPT，让 GPT 优先修复当前仓库和现有资源。
- 如果 D1、KV 或 Worker 已经创建，继续使用现有资源，不要重复创建同名或第二套资源。

## 4. 第一次进入后台

打开部署后的：

```text
https://你的网站地址/admin
```

第一次进入会看到“创建网站管理员”。按顺序填写：

1. **一次性部署口令**：部署时填写的 `INITIAL_ADMIN_CODE`。
2. **管理员密码**：10 至 128 位，至少包含文字和数字。
3. **再次输入密码**。
4. 点击“创建管理员”。
5. 系统显示恢复码后，立即点击“下载恢复码”。
6. 确认文件已经保存，再进入后台。

一次性部署口令只用于第一次初始化。管理员创建成功后，日常登录只使用管理员密码。

## 5. 后台每一栏怎么用

### 概览

- 修改浏览器标签与网站名称；默认名称是“学生作品展示”。
- 设置二维码公开访问或限制访问。
- 查看作品数、分类数、媒体数和修订号。
- 查看已经使用和剩余的网站空间。
- 查看程序版本与升级中心。

### 联系

- 修改联系区眉题、主标题、邮箱、电话和说明。
- 上传 1:1 联系图片。
- 切换“资料在左 / 图片在左”。
- 在真实画布中拖动文字；双击文字可直接修改。

### 首图与文字

- 可增加、复制、删除和排序多张首图。
- 显示模式：纯图片、系统排版、自由排版。
- 纯图片只显示图片。
- 系统排版和自由排版会在同一页面直接出现文字编辑画布。
- 修改姓名、职业标题、求职方向、个人定位和状态短句。
- 选择页面主题、展开方式和自定义字体。

### 作品分类

- 新建、改名、改颜色、排序和删除分类。
- 分类里还有作品时，必须先移动作品，不能直接删除。
- 过渡条可用系统样式，也可上传 8:1 图片。

### 作品

- 新建作品，填写名称、分类、年份、简介、难点和解决思路。
- 上传 16:9 项目封面和 MP4 成稿视频。
- 视频上传后自动读取时长；没有视频时显示 `00:00`。
- 设置封面悬浮信息、文字位置、大小、字体、颜色和对齐。
- 内容块包括：文字、图文混排、图片组、通栏图片。
- 图片组最多四张，可切换横图或竖图，排版会随数量自动变化。

### 发布

- 系统会检查首图、过渡图片、项目封面和成稿视频是否完整。
- 有必填媒体缺失时不能发布。
- 点击“保存并发布”后，访客才会看到新版本。

### 记录

- 查看最近访问、作品展开、播放请求和播放错误。
- 查看保存草稿、发布和上传媒体等管理操作。
- 网络标识使用不可逆散列，不展示原始 IP。

## 6. 图片与视频建议尺寸

系统支持 JPG、PNG、WebP、AVIF。图片上传时会尝试自动压成 WebP，并把最长边控制在 2560 像素以内；优化后的单张图片仍不能超过 8 MiB。

| 使用位置 | 实际比例 | 建议尺寸 | 构图建议 |
|---|---:|---:|---|
| 首页首图 | 自由裁切 | 2560 × 1440 | 主体尽量放在中间 60% 安全区，四周留裁切空间。 |
| 联系图片 | 1:1 | 1600 × 1600 | 人像或标志居中，边缘不要放重要文字。 |
| 分类过渡图 | 8:1 | 2560 × 320 | 使用横向纹理、场景或大留白，避免小字。 |
| 项目封面 | 16:9 | 1920 × 1080 或 2560 × 1440 | 标题文字由后台叠加，原图不要预先压太多字。 |
| 图文混排图片 | 4:3 | 2000 × 1500 | 主体偏中，左右都保留一定空间。 |
| 图片组竖图 | 3:4 | 1500 × 2000 | 同一组尽量统一色调、焦段和主体比例。 |
| 图片组横图 | 4:3 | 2000 × 1500 | 同一组尽量统一视觉风格。 |
| 通栏大图 | 16:9 | 1920 × 1080 或 2560 × 1440 | 关键内容不要贴边。 |
| 成稿视频 | 推荐 16:9 | 1920 × 1080 | MP4、H.264 视频、AAC 音频，单个不超过 50 MB。 |

### 视频压缩参考

为了控制在 50 MB 以内，可按时长大致设置总码率：

- 30 秒：约 8–10 Mbps；
- 60 秒：约 5–6 Mbps；
- 120 秒：约 2.5–3 Mbps。

以上是近似值，音频和封装也会占空间。导出后以实际文件大小为准。帧率建议 24、25 或 30 fps；没有必要为了网页播放导出 4K。

## 7. 裁切、排版与预览

- 上传图片后，系统会给出默认裁切。
- 平时预览不显示裁切虚框。
- 点击“调整”后才出现裁切框。
- 调整完成后点击“确认裁切”，虚框消失并应用结果。
- 项目封面、图文混排、图片组和通栏图都按各自固定比例裁切。
- 文字画布中可拖动位置；双击文字可直接修改。
- 封面排版改动会立即显示在真实封面预览中。

## 8. 保存草稿与正式发布

后台有三个不同动作：

1. **保存草稿**：把修改保存到后台，公开前台不变。
2. **快速预览**：保存草稿后打开 `/preview`，只给管理员检查。
3. **正式发布**：生成公开快照，访客才会看到新内容。

推荐顺序：

**编辑 → 保存草稿 → 快速预览 → 回后台修改 → 再保存 → 正式发布。**

关闭网页前如果左下角显示“有未保存修改”，必须先保存草稿。

## 9. 二维码访问

### 公开访问关闭

普通前台链接可以直接打开，不需要二维码。

### 开启限制访问

可为不同对象生成独立二维码，并设置：

- 名称；
- 最多使用次数；
- 到期时间；
- 暂停、恢复或删除。

二维码达到次数上限、过期或被暂停后会失效。不要把管理员后台地址做成公开二维码。

## 10. 密码、12 小时登录与恢复码

通俗理解：

- 第一次输入正确管理员密码后，这台浏览器会记住登录状态 **12 小时**。
- 12 小时内再次从前台点“管理”，通常会直接进入后台，不会反复要求输入密码。
- 点击右上角“安全退出”后，登录状态立即失效。
- 密码连续输错 **5 次**，后台锁定 **15 分钟**，防止别人反复猜密码。
- 忘记密码时使用系统恢复码重置。
- 恢复成功后旧恢复码立即作废，并生成新的恢复码。
- 密码和最新恢复码都丢失时，网站无法自行找回。

管理员密码、一次性部署口令、恢复码不要发送给 GPT、老师、同学或群聊。

## 11. 一个 GPT 帮不同学生部署

同一个 GPT 账号可以帮助不同学生，但 GPT 账号不会决定网站部署到谁名下。

每次开始前必须重新确认：

- 当前学生是谁；
- 浏览器实际登录的是谁的 GitHub；
- 浏览器实际登录的是谁的 Cloudflare；
- 是否还残留上一位学生的账号；
- 新网站准备使用什么唯一名称。

发现账号不对就停止部署，先切换官方账号。不能因为 ChatGPT 里是当前学生的对话，就默认 GitHub 和 Cloudflare 也已经切换。

## 12. 同一个托管账号部署多个网站

同一个 GitHub / Cloudflare 账号可以部署多个网站，但每个网站必须完全独立：

- 独立 GitHub 仓库；
- 独立 Worker；
- 独立 D1；
- 独立 `MEDIA_KV`；
- 独立网站地址；
- 独立管理员密码；
- 独立恢复码。

绝不能让第二个网站复用第一个网站的 D1 或 KV，否则内容、管理员和媒体可能串站。

建议命名：

```text
student-portfolio-姓名拼音-01
student-portfolio-姓名拼音-02
student-portfolio-姓名拼音-03
```

## 14. 常见问题

### 点击“管理”没有要求输入密码

通常是这台浏览器仍在 12 小时登录期内。点击“安全退出”，再进入后台即可验证密码门禁。

### Cloudflare 提示不同登录方式

返回登录页，使用创建账号时原来的 Google / GitHub / Apple / 邮箱密码方式。

### 项目名、D1 或 KV 已存在

说明同一账号中已有同名资源。不要覆盖旧站，给新站名称末尾加 `-02`、`-03`。

### 构建成功但部署失败

查看日志最底部。常见原因是 D1 或 KV 绑定错误、资源 ID 缺失、部署命令被改动。优先修复现有项目，不要重新创建第二套站点。

### 图片上传失败

检查格式是否为 JPG / PNG / WebP / AVIF；换一张更小的图片，或先把最长边压到 2560 像素以内。

### 视频上传失败

确认是 MP4、H.264 / AAC、文件小于 50 MB。MOV 改后缀为 MP4 没用，必须重新编码。

### 快速预览打不开

浏览器拦截了弹窗。允许当前站点打开新窗口后重试。

### 修改后前台没变化

保存草稿只影响后台。进入“发布”并正式发布后，再强制刷新前台。

### 中国大陆网络访问不稳定

`workers.dev` 在不同运营商和地区的实际表现可能不同。发布后应使用真实手机流量和宽带分别测试；后续可按需要绑定自己的域名和优化网络方案。
